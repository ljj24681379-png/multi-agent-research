# AI 产品研究团队

> 让多个 Agent 分工完成资料搜索、竞品分析、用户评价和报告生成。

**状态：第一版已完成 · 预置研究 Demo 可运行**

## 项目是什么

这是一个多 Agent 产品研究工作流实验。用户输入“研究国内 AI 搜索产品最近半年的变化”，系统把开放问题拆成资料搜集、产品分析、用户评价、竞品对比、报告整合和来源审核，并展示每一步如何交接。

## 为什么做

产品研究不是搜索结果的堆叠。真正困难的是来源质量不一、事实与观点混在一起、不同产品的比较维度不统一，以及结论很难回到原始证据。让一个 Agent 一次生成长报告，容易获得完整外观，却缺少可审查过程。

## 第一版为什么不够

单 Agent 研究常见三个问题：搜集与判断使用同一上下文，容易放大最先看到的材料；缺少独立审核，引用与结论可能错位；中间材料不可见，用户无法修正研究方向。

## Agent 分工

| 角色 | 主要任务 | 输出 |
| --- | --- | --- |
| 搜索 Agent | 找官方信息、更新记录和新闻资料 | 带来源的资料卡 |
| 产品分析 Agent | 分析定位、功能和产品变化 | 单产品分析 |
| 用户评价 Agent | 整理公开反馈和常见问题 | 观点分组与边界 |
| 对比 Agent | 统一维度、识别差异与趋势 | 对比矩阵 |
| 报告 Agent | 整合事实、推断和结论 | 研究报告草稿 |
| 审核 Agent | 检查来源、重复和证据关系 | 问题清单与发布建议 |

## 工作流

```text
研究问题
  ↓
任务拆解与范围确认
  ↓
并行资料收集
  ↓
产品 / 用户视角分析
  ↓
统一维度对比
  ↓
报告生成
  ↓
来源与结论交叉检查
```

## 预置 Demo

第一版使用脱敏静态素材模拟“国内 AI 搜索产品近半年变化”研究。页面已实现任务回放、Agent 状态、资料卡、观点与证据连接、审核结果和报告摘要；没有来源的材料不能进入关键结论。

## 产品判断

多 Agent 的价值不是同时生成更多文字，而是把相互制约的职责分开。搜集者不直接决定结论，报告生成者不能省略来源，审核者需要能把问题退回具体步骤。复杂研究因此从黑盒输出变成可回放的协作过程。
